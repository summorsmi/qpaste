## 辅助功能开关开启但粘贴仍提示未授权（2026-09-13）

系统设置中的 Qpaste 开关为开启，应用内的 `AXIsProcessTrusted()` 判断为未授权；完整退出并重启当前二进制后仍然如此。

系统 TCC 日志于 00:18:06 明确记录：`Failed to match existing code requirement for subject app.qpaste.mac and service kTCCServiceAccessibility`。授权保存的代码要求为 `cdhash a8eca31eb7967784b3244947b27c18162e0f225d`，当前应用为 `cdhash 87c73672480c858a05217c0f1ebbd307d0e73afe`，校验返回 `-67050`。

原因确定为临时签名构建更新后，已有授权仍绑定旧版本，不是尚未勾选开关。此次排查没有再次构建或更改应用签名。恢复步骤是对当前版本刷新同一项辅助功能授权；自动审批要求用户明确同意关闭/重新开启 Qpaste 开关，尚待完成。

[Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements) 说明临时签名的指定要求绑定到具体代码版本，因此不保证更新后仍匹配旧授权。

用户随后自行刷新授权并确认粘贴已可用；该结果为用户验收反馈。

## 双击 Command 快捷键（2026-09-13）

新增「双击 ⌘」快捷键选项，使用应用内和全局事件监听覆盖前后台。只对两次完整的单独 Command 按下 / 松开触发，读取系统双击间隔，键盘组合键、其他修饰键、鼠标按下、长按及重叠按下左右 Command 会中断手势。事件监听只判断事件种类和修饰键，不存储按键内容，也不拦截事件。

17 项相关测试通过（11 项历史 / 存储，6 项双击手势）。手势测试覆盖第二次松开才触发、三连按不重复触发、组合键后单击不触发、中途输入取消、超时、长按、重叠 Command 和无对应按下的松开。跨应用真实键盘触发还需新构建的辅助功能授权后验收。

[Apple 全局事件监听文档](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents(matching:handler:)) 说明全局键盘监听需要辅助功能授权，且不接收本应用自己的事件，因此另配应用内监听。切回普通快捷键时会移除这些监听。

最终 Release 构建及签名校验通过，已启动新版本。真实设置界面显示 5 GB，保留条数菜单出现「不限」，快捷键菜单出现「双击 ⌘」。仅打开菜单检查，用户已有的「1000 条」「不按时间清理」「⇧⌘V」偏好保持原样。新构建的授权状态为未授权，仍需用户刷新同一项辅助功能开关。

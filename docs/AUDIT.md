# 当前版本检查（2026-09-13）

后续更新：下文建议中的“正文按需读取”已实现，升级方案与新旧版本内存对比见 [LAZY_CONTENT.md](LAZY_CONTENT.md)。本文表格保留原检查时的数据。

基线为 `92b24b8`。检查顺序：功能缺陷、易用性与资源占用、后续功能。
使用隔离目录、命名测试剪贴板和合成数据；不向用户历史插入样例。

## 已修复：悬浮详情快速往返不显示

指针在详情出现前离开条目，随后在 250 毫秒关闭等待期间回到同一行，旧逻辑会取消显示任务又跳过重新调度，导致停留再久也不显示详情。
现在只有已显示的详情才能复用；尚未显示时重新计时。

新增测试在修复前失败，修复后全部 7 项悬浮测试通过，覆盖完整文字、长图滚动和非激活详情窗口。原生测试只注入命令行宿主无法获得的键盘焦点边界，不作为真实鼠标悬浮验收。

## 已修复：无变化的定时清理打断列表

原来每分钟检查保留策略都会重查当前列表，将 `selected` 临时置空、禁止点击、重新创建详情。即使没有任何记录被删除，也可能打断正在查看的文字选区或图片。
现在只在实际删除记录或补存成功时刷新；无变化的清理不会取消正在进行的搜索。

新增测试在修复前失败，修复后全部 5 项分页测试通过。另验证真正改变保留数量时，列表和全局统计仍更新，失败捕获补存后仍可见。

## 已优化：长文本列表摘要

标题原来先分割全文的所有行，代码识别也会创建清理后的全文。现在标题只读取首个非空行的最多 160 个字符；代码识别只检查去掉开头空白后的前缀。完整正文和搜索内容不变。
增加 Unicode 字符、换行、空白文本与代码识别回归。性能数据在本文后续测量部分记录。

## 已优化：大图预览按显示尺寸解码

列表缩略图继续使用最长边 168 像素。完整模式的常驻详情和精简悬浮详情改用独立的显示预览：不放大小图，宽度最多 1400 像素，总像素最多约 800 万，保留长图全部高度。仅显式打开大图查看器时加载原图；再次复制和粘贴仍读取原始 PNG。
新增实际 PNG 测试验证显示预览为 1400×800，而大图查看器和剪贴板仍保留 2800×1600；长图限额与原始文件内容不变。

使用 Image I/O 的缩略解码接口，依据 [Apple 图像内存说明](https://developer.apple.com/videos/play/wwdc2018/416/)。缓存额度是回收提示，不是整个进程的硬上限，见 [Apple NSCache 文档](https://developer.apple.com/documentation/foundation/nscache/totalcostlimit)。

## 已修复：富文本在大小限制前就被解析

仅提供 RTF 的剪贴板原来先完整解析文档，再检查正文长度，超大格式数据也能进入解析器。现在 RTF 超过 2 MB 时不进入解析；若同时提供了普通文本，仍正常记录普通文本，只省略过大的格式数据。

使用带超大可忽略 RTF 分组、正文仅为 `visible` 的合成样例验证解析边界。macOS 会给 RTF 自动提供普通文本类型，因此测试分别覆盖原始 RTF 回退解析与真实剪贴板的普通文本回退；本项只限制 Qpaste 自身的 RTF 解析，不声称控制系统剪贴板服务的格式转换。日期集成测试同时改用微秒容差，避免时间在 JSON / SQLite 基准之间转换时的浮点舍入导致偶发失败。

## 性能测量

macOS 26.6.2、arm64，Release 构建，独立测试进程。各次操作后清理临时自动释放对象；没有渲染数千行真实界面，因此以下是存储 / 列表模型测量，不等于用户操作的完整响应时间。

复测：`QPASTE_BENCHMARK=1 bash scripts/test.sh -c release --filter PerformanceTests`。默认回归不运行压力测量。

| 场景 | 实测结果 | 判断 |
| --- | --- | --- |
| 实际安装版，8 条现有记录，空闲 | 检查开始时 RSS 约 107 MiB，CPU 0.0% | 日常空闲未见异常占用；单次观测不能证明长期无泄漏 |
| 10000 条，每条约 1 KiB | 初始 80 条约 26 ms；搜索最后一条约 182 ms | 一万条普通短文本的查询量级可用 |
| 400 条，每条约 128 KiB | 搜索约 589 ms；加载全部约 35 ms；正文合计 50 MiB | 全文扫描成本随总正文量增加 |
| 上述 400 条连续加载后刷新 | 加载完 RSS 约 107 MiB，刷新后阶段 RSS 约 208 MiB | 含测试宿主、解码和分配器保留内存，不能当成内存泄漏证据；确有累计加载和刷新占用问题 |
| 400 条长文本摘要各计算 10 次 | 优化前 4889 ms，优化后约 362 ms | 本组摘要微基准约快 13 倍，不代表鼠标操作整体快 13 倍 |
| 80 条短文本摘要各计算 10 次 | 原实现约 8 ms，优化后约 73 ms | 有短文本常数开销取舍，平均一次 80 条摘要约 7 ms；后续可继续微调 |
| 6000×4000 PNG 常驻 / 悬浮预览 | 解码由 6000×4000 变为 1400×933；像素存储约 91.6 MiB → 5 MiB | 原图未改；这不是整个应用 RSS 的下降量 |

## 尚未实施的优化，按优先级排序

1. **大量历史的正文按需读取。** 当前每加载一页都会保留该页完整正文 / RTF，连续往下滑会累计；刷新又重新解码已加载条目。建议列表只读取摘要、时间、来源与图片标识，选中后再读取正文；正文和旧页使用有上限的缓存。这是下一轮最值得做的资源优化。
2. **减少主线程的存储工作，并取消过期数据库搜索。** 查询结果虽在后台读取，但复制保存、图片编码和保留策略仍有同步工作；搜索取消目前只丢弃旧结果，不中断正在执行的全文扫描。大量记录时应优先让写入异步、对运行中的查询加取消，再依据实际大数据表现决定搜索索引方案。
3. **明确长期存储与失败暂存的边界。** 5 GB 是普通历史的内容额度，不包括数据库重复搜索字段、索引、复制事件、旧备份及收藏 / 片段。磁盘满或写入失败时，内存暂存队列也没有上限。建议补充磁盘实际占用统计，并在暂存量过大时清楚提示和暂停继续捕获，避免静默丢记录；本轮没有擅自改变保留规则。
4. **更容易从空搜索结果中恢复。** 保留单一搜索框；只在无结果且存在分类 / 日期限制时，提供一次点击搜索全部范围的入口。精简模式保持图标导航和双击粘贴。
5. **把已有能力放到右键菜单。** 可以补上“复制为纯文本”和“查看大图”，减少依赖隐藏快捷键、切换模式或悬浮精细操作；不增加常驻按钮。

0.5 秒轮询仍可能漏掉间隔内连续复制的中间内容，这是已有机制边界，本轮未更改。文件历史仍保存路径，不是文件备份。

## 适合增加的功能

按当前个人使用、图片 / 文本历史与简洁界面偏好，建议依次考虑：

1. **空格快速预览。** 选中条目按空格查看完整文字或可缩放图片，Esc 回列表；尤其补足精简模式看大图的路径。
2. **图片提取文字。** 在图片右键菜单提供按需识别、复制识别结果，优先采用本机处理；不默认为每张图片后台识别。
3. **手动备份与恢复。** 导出收藏、片段，或包含图片的全部历史；导入前显示数量并去重。先做手动操作，不增加账号或同步设置。

本轮只评估这些新增功能，没有实现它们。删除流程与现有保留偏好保持原样。

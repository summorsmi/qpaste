# 前三项性能优化 · 2026-09-14

本轮实现了[性能审查](PERFORMANCE_AUDIT_2026-09-14.md)中的前三项：长文本悬浮尺寸、图片后台处理和搜索执行。保持现有界面布局、正文内容、图片格式与去重规则；没有更改数据库 schema 或搜索匹配语义。

## Release 同样本结果

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 10,000 条约 1 KiB 文本，搜索最后一条 | 194.3 ms | 86.1 ms |
| 400 条约 128 KiB 文本，搜索最后一条 | 617.7 ms | 305.5 ms |
| 长文本首次悬浮尺寸计算 | 225–247 ms | 116.3 ms |
| 同内容、字体和可用尺寸重复测量 | 每次重新排版 | < 0.1 ms，命中缓存 |
| 6000×4000 图片首次预览请求占用主线程 | 94.5 ms，同步解码 | 0.1 ms，后台完成约 49.1 ms |
| 6000×4000 图片采集主线程提交 | 转码 112–116 ms，加入历史另约 49 ms | 0.7 ms，后台完整采集约 151.6 ms |

图片的主要改善是从主线程移走工作，不代表全部处理只需要 0.7 ms。前后的图片采集测量边界不同：优化前分别测转码及加入历史，优化后测 poll 返回和整个异步链路；未据此计算整体倍数。后台预览耗时也受文件缓存和线程调度影响。

搜索沿用原有 PerformanceTests 的同步查询测量模式，不包含生产环境 120 ms 输入防抖。数据为同一台 Mac 上的合成样本，不是用户真实历史的 P95 结果。原有摘要与正文缓存继续保留；本轮未声称常驻内存下降或完成泄漏检测。

## 实现

- 长文本：保留精确宽度计算；对于最终高度已确定为最大值的长原文，省略第二次排版。缓存最多 32 组“截取样本、是否截断、字体、可用宽高”的结果，不持有整篇长原文。
- 搜索：使用只含 ID 和日期上下文的物化匹配集合，让结果总数和当前页复用同一次匹配；完整正文只在页面选定后读取。查询词使用 SQLite 辅助数据缓存，保持原来的本地化子串匹配函数。查询取消通过进度回调中断正在运行的 SQL，并在结束后移除回调；分类与容量统计按数据变更代次更新。
- 图片采集：主线程只读取剪贴板快照与来源、时间信息；串行后台处理转码、指纹、缩略图，再进入原有持久化队列。保留原来的 PNG 规范化过程和图片去重结果。
- 图片预览：后台解码缩略图、详情与原图，合并相同的在途请求。缩略图使用独立队列，不把正在选择的详情排在大量缩略图任务后面。
- 图片粘贴：文件读取与 TIFF 准备在后台，最终写剪贴板仍在主线程，取消的操作不会写入剪贴板。
- 图片缓存：按解码尺寸实行明确的 12 / 32 / 60 MiB 上限及条目上限。放大窗口当前展示的原图可以超出缓存额度，单独持有直到关闭；关闭后完成的旧请求不会重新固定该原图。

## 异步一致性

连续复制按快照时间和串行队列顺序保存。与后台处理重叠的删除、清空会禁止旧快照重新插入对应记录，同时保留不相关的新采集。收藏修改在持久化队列内读取最新记录后执行，避免覆盖较新的复制信息。

退出时先等待已经接受的采集，再应用完成回调并执行存储 flush。写入失败保留待重试内容和同一个复制事件标识；重试不生成重复条目或重复事件。存储的同步持久化保证保持不变。

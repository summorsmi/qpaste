# 列表摘要与正文按需读取

## 数据库阶段

新增独立的 `HistoryListItem`，只包含最多 160 字的标题、类型、来源、时间、收藏状态与图片标识，不包含正文、RTF 或文件路径列表。摘要使用独立版本标识，旧摘要不能读取已被修改的正文。

数据库 schema 2 → 3 补充摘要与版本列，逐条读取旧记录生成摘要，原 `payload` 字节和复制事件保持不变。升级在事务内执行，任何失败都会回滚新增字段。版本 1 与旧 JSON 也可直接升级。

`listPage` 与完整记录查询使用相同的分类、日期与全文搜索条件，但只返回摘要。正文按 ID 和摘要版本单独读取，按日期筛选时仍展示该时间范围内的来源和复制时间。

16 项核心相关测试通过，覆盖升级与失败回滚、原字段字节保留、完整正文末尾关键词搜索、日期上下文、格式保留、旧版本摘要失效，以及即使正文无法解析仍能独立读取摘要。

## 界面与正文缓存

列表只保存摘要。选择记录时在后台读取正文；悬浮停留达到原有显示时间后才请求该条正文。快速切换选择、移出悬浮区域或关闭详情时，取消过期请求，读取完成也不会重新弹出已经关闭的详情。

正文缓存按最近使用顺序淘汰，同时限制最多 12 条、约 8 MiB 内容大小。超出缓存额度的单条内容仍可查看，只是不留在缓存。当前显示 / 编辑的正文、图片缓存和系统界面本身另需内存，因此这不是整个应用的内存上限。

复制、粘贴、纯文本还原与片段编辑先取得完整内容，不使用列表摘要。日期筛选的历史来源和时间保持不变。修改、收藏、删除及清理后使旧缓存失效；读取失败显示错误，不使用截断内容替代正文。保存失败的暂存内容仍可完整读取。

74 项功能测试通过（39 项应用测试、35 项核心测试），性能测试另行启用通过。新增覆盖：180 条带长正文 / RTF 的多页加载、缓存数量和字节上限、未选中记录的完整复制、片段完整编辑及版本失效、快速选择和取消、正文损坏、暂存正文、异步详情关闭。原有悬浮测试改为等待实际显示 / 关闭完成，避免并行测试占用主线程时依赖固定 60 毫秒造成偶发失败。

## 同样本性能对比

修改前使用提交 `9d0e0ec` 的临时独立副本；修改后使用本轮代码。两者在同一台 Mac、Release 构建下先后运行 `PerformanceTests`，每次操作后释放临时对象，未与其他测试并行。

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 400 条长文本，每条约 128 KiB，加载全部后的 RSS | 107 MiB | 50 MiB |
| 上述列表新增一条后刷新的阶段 RSS | 209 MiB | 51 MiB |
| 上述列表加载全部耗时 | 31.6 ms | 14.6 ms |
| 上述列表新增并刷新耗时 | 39.9 ms | 16.9 ms |
| 上述长文本全文搜索 | 617.6 ms | 613.7 ms |
| 10000 条短文本全文搜索 | 189.3 ms | 186.3 ms |

400 条长文本原来累计持有约 50 MiB 正文；修改后列表标题合计约 62 KiB，正文缓存约 257 KiB（首次选择和搜索结果两条）。摘要还包括 ID、来源、时间等字段，62 KiB 不是摘要的全部内存。

这些是隔离测试进程的阶段测量，不是完整应用的常驻内存承诺，也不等于内存泄漏检测。搜索机制保持不变，因此预期搜索耗时接近；本轮主要消除了已加载正文累计驻留和刷新时批量重新解码。
